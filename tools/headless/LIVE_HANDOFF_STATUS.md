# Live Ambient-to-Netplay handoff prototype (Mac only)

This branch is a protocol/test prototype, **not a shipping Just Play feature**. Do not expose its switch action in Android or merge it into the release library. The device's original ROM, SRAM, and firmware owners must remain untouched until the production coordinator and recovery policy are complete.

The `litev-handoff-integrate` worktree rebases this prototype onto core `e7e717c4`, retaining the newer Ambient queue-generation and slowdown tracking. Its Mac parity build (the 216 enabled `LITEV_*` options from the previous handoff build), `ambient-queue-test`, and `ambient-slowdown-test` pass. The integrated two-process Pokémon Black/White gates pass for a normal cut (`/private/tmp/codex-handoff-integ-gate-17920`), a failed PREPARED vote followed by a fresh retry with delayed RESET_DONE and stale-epoch replay (`/private/tmp/codex-handoff-integ-retry-17930`), and a one-sided live-start response failure (`/private/tmp/codex-handoff-integ-afterlive-17940`). All three gates end back in Ambient with source saves unchanged. This is Mac-only validation; no RG DS test or production promotion was performed.

The two-process cut test uses sequenced Ambient MP packets, a consumed-watermark FENCE/READY barrier, scratch-loaded peer savestates and firmware, provisional PREPARED/ARMED/GO votes, a checkpoint-bound TCP live-start rendezvous, and a frame-zero proof gate before any replica frame. The proof carries the handoff epoch/token and first input over an explicit coordinator-supplied UDP endpoint and accepts only the expected source address/port. It prevents stale/wrong-port first inputs, **not active LAN impersonation**. The test then deliberately rolls back to the frozen Ambient sources. An aborted offer crosses reliable ABORT and RESET_DONE messages before retry; epochs increase on the same link, and old-epoch controls are ignored. The test-only swap trial moves the exact local and remote scratch NDS objects that were loaded before PREPARED into Lockstep; it does not reconstruct them from checkpoint files. Their userdata and scratch save paths remain attached until teardown.

Run the scripts in this directory with a Mac headless build and explicit ROM, source-savestate, source-save, and input-script paths. `test-live-handoff-cut.sh` takes `HEADLESS ROM_HOST ROM_GUEST STATE_HOST STATE_GUEST SAVE_HOST SAVE_GUEST INPUT_HOST INPUT_GUEST OUT_DIR` and requires `LITEV_HANDOFF_TEST_IP` set to the Mac's LAN IPv4 address. Its presence, transfer, and Netplay ports can be isolated with `LITEV_HANDOFF_TEST_PRESENCE_PORT`, `LITEV_HANDOFF_TEST_TRANSFER_PORT`, and `LITEV_HANDOFF_TEST_NETPLAY_PORT`. For a first-offer fault followed by a fresh on-wire retry, set `LITEV_HANDOFF_EXPECT=retry` and `LITEV_HANDOFF_TEST_FAULT=host:prepared`; `LITEV_HANDOFF_TEST_STALE_REPLAY=1` replays the closed FENCE, and `LITEV_HANDOFF_TEST_SLOW_RESET_ROLE=client` delays client RESET_DONE by 250 ms. `host:aftergo` and `host:afterlive` are asymmetric-transition regression faults with `LITEV_HANDOFF_EXPECT=abort`. Both scripts named `test-live-handoff-{plain,hosted}.sh` take `HEADLESS ROM_HOST ROM_GUEST STATE_HOST STATE_GUEST FW_HOST FW_GUEST SAVE_HOST SAVE_GUEST OUT_DIR` and replay 600 frames from exact cut checkpoints.

Production blockers:

1. **No Android live coordinator or ownership-safe adoption.** The current app Netplay conversion stops and reloads the ROM. The Mac-only harness now runs the exact scratch NDS objects prepared before the vote, but deliberately rolls back and does not prove Android `MelonInstance` promotion. Android must stage every replica with isolated cart-SRAM and firmware SaveManagers *before* any checkpoint load, then promote the actual prepared objects without changing the owner's paths. Loading a savestate can write cart SRAM immediately.
2. **No durable commit/in-doubt recovery or automatic return.** GO, TCP response, and first UDP input each have asymmetric-loss edges. Current gates prevent the tested pre-frame faults but cannot make distributed promotion atomic. The frame-zero proof has only been exercised for the two-player *plain* trial; Hosted's dedicated server/record stream needs a separate startup design, even though its saved checkpoints replay for 600 frames. If a peer disappears after one endpoint advances, recovery needs retained sources, a rendezvous/journal policy, and a coordinated result. Returning to Ambient must use the *final* local Netplay console/SRAM/firmware, not the frozen pre-handoff source; the old Ambient link may time out during a long Netplay session.
3. **No peer authentication or confidentiality.** The full savestate (including SRAM) and SPI firmware cross plaintext TCP. The Ambient device ID is a claim and its control-token is visible on the LAN, not cryptographic proof. The frame-zero proof rejects stale/wrong-endpoint packets but an observer able to replay the public token from the expected endpoint can still impersonate; subsequent ordinary Netplay UDP input is not session-bound either. Do not expose a user-facing transfer until identity, encryption, and privacy/consent policy are resolved.
4. **No pre-cut exact-ROM roster.** Ambient discovery has game code/build but not peer ROM SHA-256/size. Pokémon Black/White and ROM variants require exact peer ROM lookup/cache and any transfer consent *before* freezing; existing Netplay ROM exchange is tied to restart-based `loadRom`.
5. **Broad regression gates remain.** Build parity is now a compatibility id, not the binary: `NetplayHandoffCompat()` (handoff protocol + every enabled LITEV option except host-only ones, CMakeLists.txt) binds the Ambient BuildID, the checkpoint header and the live-start manifest. Checkpoints are saved with `Savestate::ColdCaches`: the JITS, A7HL and A9HL sections (build-stamped, so another build discarded them and diverged at once) are reset on the live console exactly as a loader resets them and saved empty. Verified Mac-only across two different builds (`LITEV_AMBIENT_CUT_LIVE_LOCAL=1`, live consoles keep playing, scripted walking): 6000 and 15000 Netplay frames, every 60-frame sys/PC/RAM checkpoint of both consoles identical across processes; the old warm checkpoints (`LITEV_HANDOFF_WARM_CHECKPOINT=1`) fail the pre-commit proof. `LITEV_TEST_PROOF_STATES=s0|fw0|rom0|s1|fw1|rom1` runs the proof on two checkpoint files. Check DS/DSi and savestate config, MAC/firmware, wrong-IP/same-IP attacker, transfer corruption/timeout, background/stop, save-file integrity, multi-peer/no-handoff performance, and actual linked trade/battle after migration before release.
